---

## 1. 项目背景

用户在拍下大量书籍封面后，希望把这些照片自动整理成结构化的"我的书库"。当前流程完全手动（一张张看、抄书名、查作者、写表格），效率低、容易遗漏。

需要一个工具：拍照 → 自动识别书的信息 → 自动同步到 Notion，让书库随时可查询、可分类、可分享。

---

## 2. 项目目标

### 2.1 业务目标
- 几秒内把一张书的封面照片变成 Notion 数据库中的一行结构化记录
- 支持单张和批量上传（手机现场拍 + 电脑批量拖入）
- 支持长期增长（最终可能积累 500-1000+ 本书）

### 2.2 技术目标 / 学习目标
- 完整的端到端全栈项目，可作为求职作品集
- 使用现代主流技术栈：Next.js + TypeScript + Tailwind + Vercel
- 集成两个真实第三方服务：Anthropic Claude API（视觉识别）+ Notion API（数据存储）
- 部署到公网，可在手机/电脑通过浏览器访问

---

## 3. 用户故事

1. **作为读者**，我希望对着书架拍一张照片，应用自动识别出书名、作者、类型，并把这本书加进我的 Notion 书库，这样我就不用一本本手抄
2. **作为读者**，我希望一次上传多张照片（比如刚从图书馆借了 10 本书），应用并行处理后批量写入 Notion
3. **作为读者**，我希望在手机上现场拍照后立即上传，不用等回到电脑前
4. **作为读者**，我希望识别结果不准时可以在结果页修改后再写入 Notion，避免"垃圾数据"污染书库
5. **作为求职者**，我希望这个项目部署到公网，简历里能放链接给面试官看

## 4. 功能范围（MVP）

### 4.1 必须有（Must Have）

| # | 功能 | 描述 |

| F1 | **图片上传** | 单张/多张图片上传；支持拍照（手机）和文件选择（电脑）；支持 HEIC/JPG/PNG |
| F2 | **图片预处理** | 后端自动把 HEIC 转 JPG；超过尺寸的图片压缩到 1600px 宽、JPEG quality 85 |

| F5 | **写入 Notion** | 通过 Notion API 在指定 Database 创建一行，并把封面图上传到该行的 "Files & Media" 列 |
| F6 | **错误处理** | 网络失败、API 失败、识别失败时有清晰提示并允许重试 |
| F7 | **部署上线** | 部署到 Vercel，可通过公网 URL 访问 |

│  └─────────────────────┘    │
│  ┌─────────────────────┐    │
│  │ 后端 API Routes      │    │
│  │ - POST /api/process  │    │
│  │   1. 接图、转格式     │    │
│  │   2. 调 Claude 视觉   │    │

### 5.2 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | **Next.js 15+ (App Router)** | Vercel 原生支持；前后端一体化；TypeScript 一流支持 |
| 语言 | **TypeScript** | 类型安全；写起来更顺；面试加分 |
| 样式 | **Tailwind CSS** | 写得快；不用切文件；社区主流 |
| UI 组件（可选） | **shadcn/ui** | 复制粘贴式组件，能用就用；不依赖也行 |
| 后端 | **Next.js Route Handlers**（`app/api/*/route.ts`） | 跟前端同一个项目，一次部署 |
| AI 视觉 | **Anthropic Claude API**（@anthropic-ai/sdk） | 中文识别强；JSON 输出稳定 |
| Notion 集成 | **@notionhq/client** | Notion 官方 SDK |
| 图片处理 | **sharp** | 业界标准；支持 HEIC 输入 + JPG 输出 + 压缩 + 缩放 |
| 部署 | **Vercel** | GitHub push 即自动部署；免费档完全够 |
| 版本控制 | **GitHub**（public 或 private repo） | 标配；连 Vercel 用 |
| 本地开发 | **VS Code + Claude Code** | 用户选择 |

### 5.3 数据流转细节

**单张图片处理流程：**
1. 用户上传图片（multipart/form-data）
2. 服务端用 `sharp` 读取 → 检测格式 → 转 JPG → 缩到 max 1600px → 输出 buffer
3. 把 buffer 转 base64，发给 Claude API，要求**严格 JSON 输出**（含 `title`, `subtitle`, `author`, `country`, `genre`, `description`）
4. 解析 JSON，如果识别失败返回结构化错误
5. 把图片 buffer 通过 Notion 的 File Upload API 上传到 Notion，拿到 file_upload_id
6. 调 Notion `pages.create` 创建一行，把刚刚的字段填入对应属性，并把封面字段指向 file_upload_id
7. 返回成功 + page URL 给前端

## 6. Notion Database 结构

需要在 Notion 中预先创建一个 Database，建议字段：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| 书名 | Title | ✅ | 主标（不含副标） |
| 副标题 | Text | | 冒号后的部分 |
| 作者 | Text | ✅ | 多作者用 "&" 或 ", " 分隔 |
| 国家 | Select | | 作者国籍 |
| 类型 Label | Multi-select | ✅ | 回忆录、心理相关、励志、儿童读物等 |
| 描述 | Text | | 一句话主题 / 封面可见信息 |
| 封面 | Files & Media | | 上传的封面 JPG |
| 录入时间 | Created time | 自动 | Notion 自动维护 |
| 原图文件名 | Text | | 调试用：上传时的原始文件名 |
| 状态 | Select | | 草稿 / 已确认（用于人工审核流） |

## 7. 用户界面（UX 概要）

### 7.1 页面清单

| 页面 | 路径 | 作用 |
|------|------|------|
| 上传页 | `/` | 选择/拍摄图片，发起识别 |
| 结果页 | `/result/[batchId]` | 展示识别结果，允许编辑后写入 Notion |
| 历史页（可选） | `/history` | 看最近上传的几本书的链接（直接跳 Notion） |

### 7.2 关键交互

- **上传页**：大按钮"拍照 / 选图"，支持拖拽和点击；选了图后立刻显示缩略图，按"开始识别"提交
- **处理中**：进度条 + 当前正在处理第几张
- **结果页**：每张图一张卡片，左封面右字段（可编辑），底部"确认入库"按钮
- **错误态**：识别失败的卡片高亮，附"重新识别"和"手动填写"

## 8. 安全和隐私

- API Key 仅在服务端使用，不暴露到前端
- 用户上传的图片只在内存中处理，处理完不持久化到服务器
- 所有数据进 Notion；服务器不保留任何用户数据
- 部署到 Vercel 时所有 env 变量加密存储

## 11. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| Claude API 识别中文/装饰字体准确率不够 | 数据质量 | 允许用户在结果页编辑 |
| Notion API 速率限制 | 批量上传变慢 | 加 SDK 内置 retry + 客户端进度展示 |
| Vercel 函数 10s 超时（免费档） | 大图 + 慢 API 可能超时 | 图片预压缩；任务拆分；超时降级 |
| HEIC 在某些环境无法解码 | 上传失败 | sharp 通常支持；失败时返回明确错误 |
| Anthropic API 月度成本超预算 | 钱包 | 加调用计数；超过阈值告警；预估 88 张 < $1 |

## 12. 关键决策记录（ADR 简要）

- **不做用户系统** —— 首期只一个用户，Token 写 env，简化巨大
- **不存数据库** —— 数据全在 Notion，服务器无状态，部署简单
- **前后端一体（Next.js）** —— 一次部署，比拆 Python 后端 + 前端简单 10 倍
- **用 Anthropic 不用 OpenAI** —— 中文识别更稳；JSON 输出更准
- **用 sharp 不用 ImageMagick** —— Node.js 原生 binding，Vercel 函数能跑
